🚀 Getting Started with LoadForge

LoadForge is a high-concurrency, local-first performance testing and observability platform designed to answer critical API scalability questions during every load benchmark.

⚡ Single Executable Binary Releases

Download pre-compiled binaries for macOS, Linux, and Windows from GitHub Releases:

Quick Start Command

Run the binary executable from your terminal:

bash — Terminal Command 
./loadforge -port 8080 -browser

CLI Command Flags

Flag Default Value Description
-port 8080 HTTP server port for dashboard UI & REST API endpoints.
-db ~/.loadforge/loadforge.db Path to SQLite local storage database file.
-browser false Automatically opens web dashboard in system browser on startup.

⚡ Traffic Load Patterns

LoadForge supports 6 core load profile generation strategies to test baseline capacity, traffic ramps, and breaking point limits.

Constant Load

Maintains a static number of virtual users (VUs) for a set duration (e.g., 100 VUs for 5 minutes). Best for steady-state throughput testing.

Ramp Up / Ramp Down

Gradually increases or decreases user concurrency over time (e.g., 10 → 500 VUs over 2 minutes). Pinpoints exact degradation thresholds.

Spike Test

Suddenly surges traffic (e.g., 20 VUs → 2,000 VUs in 5 seconds). Tests system recovery and circuit breaker handling.

Breakpoint Auto-Stop

Steadily escalates load until error rate exceeds threshold (>5% 5xx) or P95 latency exceeds maximum limits. Auto-stops on failure.

Convert OpenAPI/Swagger specs, Postman collections, cURL commands, or HAR files into LoadForge test scenarios in one click.

cURL Importer Example

Paste any cURL command directly into the Importer tab. LoadForge parses the method, target URL, HTTP headers, and request body payload automatically.

bash — cURL Import String 
curl -X POST http://localhost:8080/api/mock/echo \
  -H "Content-Type: application/json" \
  -d '{"sku": "ITEM-101", "qty": 2}'

📊 Metrics, Quantiles & Timing Waterfalls

Understand how LoadForge calculates requests per second (RPS), tail latency quantiles, and timing waterfalls.

Metric Definition Why It Matters
Total RPS Requests handled per second across all virtual users. Measures overall server throughput capacity.
P50 (Median) Response time experienced by 50% of requests. Represents average user speed.
P95 / P99 Line 95% and 99% of requests were faster than this time. Reveals tail latency for worst-case heavy users.
TTFB Waterfall Time to First Byte (DNS + TCP + TLS + Server Processing). Pinpoints server backend code vs network delays.

WebSocket endpoint broadcasting live telemetry snapshots.

🛡️ Security & Privacy Policy

⚠️ Authorized Testing Disclaimer

Only load test applications and servers you own or have explicit permission to test.

LoadForge runs locally, binds to localhost loopback interfaces, and automatically masks Bearer tokens, API keys, and passwords (`[MASKED_SECRET]`) in report exports.
